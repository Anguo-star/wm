总体路线：两类数据，一条研究主线

FineART 负责训练表示对照；RoboTwin 负责真正的动作干预和闭环成功率验证。

DATA → REPRESENTATION → PREDICTION → CONTROL

端到端实验脉络

可并行准备，按 Gate 依次推进
语义动作训练 未来预测训练 关键决策点
核心假设：将动作抽象为可执行的文本指令后，增加对「执行后实际发生什么」的显式监督，有机会提升行动选择与错误恢复。整个过程不要求生成未来图像，但必须验证预测是否对动作变化敏感。
WHY FINEART?

天然具备时间对齐的语言

40,543 条双臂轨迹、533,913 个子任务、151 项任务；比从零构建动作语义标注更适合做第一轮受控实验。数据集 ↗

WHY NANOASTRA?

文本动作接口无需另训动作头

进度描述与可参数化动作原语采用统一语言输出，便于在同一生成接口中增设未来后果预测。方法与训练细节 ↗

WHAT IS NEW TO TEST?

预测必须带来决策增益

仅有“文字状态预测”并不是新颖性；需要证明动作敏感的后果建模，优于普通 CoT、额外采样与无预测打分。最接近工作 SWM ↗

PRE-FLIGHT / BEFORE TRAINING

先解决数据能否被公平比较

这一步比模型结构更重要；否则后面即使 loss 降了也很难解释。

优先实施
CHECK 01

14D 关节动作 → 语义动作原语

FineART 原始动作是双臂 14 维关节/夹爪目标；nanoAstra 的 move / rotate / gripper / wait 则主要围绕末端位姿表达。两者不是现成的同一标签格式。

  • 核实机器人 URDF、FK、夹爪标定、关节单位、时间戳；判断 EEF 轨迹是否可从 joint state 重建。
  • 动作区间内基于 FK 计算末端 Δxyz/ΔR；关节轨迹与执行结果保留用于回放与误差计算。
  • 先抽检 30–50 个 episode：量化位姿/夹爪转换失败率；确认语义动作经过 IK/控制器能执行。
  • 降级路径：如果运动学或外参缺失，先用 joint-relative 的文本动作语义做 SFT，不假装实现了 nanoAstra 的空间坐标标准化。
原始 FPS：30状态 / 动作：14D相机：4 路
CHECK 02

分清“当前子任务”和“未来实际状态”

FineART 的 language_persistent 是各时间段的人类子任务说明，可以直接监督 progress / subtask；但不是「动作执行后物体真的到了哪里」的 future-state ground truth。

  • 阶段 1：使用已有 subtask 标注，核对区间与图片/动作同步，不强制生成新的未来 caption。
  • 阶段 2：取 动作执行结束后的真实观测 ot+Δ 或仿真 object/contact state，再生成受约束的语义状态标签。
  • 对于动作改变后的结果：FineART 只提供实际执行的一条轨迹；不能凭空把其他候选动作当作已有真值。
  • 做固定轨迹划分：数据原生只有 train split，必须按 episode_index 独立拆分，额外设置 held-out tasks。
40,543 episodes533,913 subtasks约 1.86 TB 全量

01 / SUPERVISED FINE-TUNING
01

阶段一：处理前后 SFT 对照

目标不是追求完整 nanoAstra 规模，而是归因“哪些数据变换真正有效”。

近期主任务

第一轮只训四个可解释的版本

统一基座：Qwen3.5-9B；统一 FineART 切分、相机/状态输入、训练资源预算。先使用 LoRA/QLoRA 小样本验证，之后再扩容。

实验时间 / 动作标签语言内容核心问题
R0 原始基线固定时间窗的 14D joint action tokens任务指令 + 当前图像/状态不使用事件语义化的数据，单纯把原始动作串行化后 SFT 能做到什么？
R1 事件对齐行为事件切分；joint-space 段动作任务 + FineART subtask / progress事件采样＋语义进度是否比固定窗有效？可加「无 progress」消融。
R2 语义动作与 R1 完全相同决策点；换成 EEF primitive与 R1 相同的语言目标R1 → R2 尽量只测试动作表示转换，而不混入时间/语言因素。
R3 完整配方沿用 R2结构化机器人 system prompt / 进度 / 动作增加 CP-SFT 风格约束、通用 VQA 混合、数值 token loss；逐项移除做消融。
公平性底线：报告同一批 episode 的物理运动时长、决策点数、训练 token 预算与优化步数；R0→R3 是完整工程链的总体对比，不能单凭这组差异声称“语义动作是唯一原因”。R1↔R2 才是主要表示实验。

数据样例：SFT 标签如何变化

{
  "task": "Move the blue block to the tray",
  "t": 4.20,
  "image": "cam_high + wrist views",
  "state": [q₁, ..., q₁₄],
  "target": [[a₁,...,a₁₄], ...]
}
// 简化示意；不是 FineART 的逐字段原始 JSON
演示标签结构，不代表从 FineART 取出的真实轨迹。R2 的 EEF primitives 必须来自经过审计的运动学转换。

评估方式

  • 动作可执行性：JSON/指令解析率、关节越界与 IK 失败率、动作/夹爪事件合法率。
  • 对齐后的行为误差：末端位置/旋转偏差、夹爪切换误差、动作持续时间偏差；需要统一物理终点。
  • 语言作用：子任务预测准确性、progress 是否与当前观测一致。
  • 保留能力：同一套独立 VQA/空间问题集的前后差异，防止 SFT 导致灾难性遗忘。
  • 有条件的闭环：若完成机器人接口与仿真对应，报告实际 success；否则明确仅是离线验证。
训练设置：首轮 200–500 条 episode；相机先 1–2 路、冻结基座配置、固定 seed。分数应按任务和多 seed 汇总，不用单一 loss 决定最终方案。

02 / LANGUAGE FUTURE WORLD MODEL
02

阶段二：未来语义预测 → 决策闭环

不做未来图像生成；预测动作执行之后，哪些任务相关的事实发生了变化。

核心研究实验

同一 VLM 的两种调用能力

先提议动作，再以该动作为条件预测未来后果；可以是同一组模型权重、不同的 prompt / target，而不是强制另设视觉 WM。

(imageₜ, robot_stateₜ, history, actionₜ) → future_semanticsₜ₊Δ
预测字段只保留可验证事实：夹持状态、对象相对位置、接触/碰撞、目标推进、明确的失败后果。允许必要的距离/角度数值；不把“我会成功”作为状态标签。
建议输出层级二值接触对象关系数值偏差任务阶段

推理闭环示意

实线：本轮动作选择　·　虚线：下一轮观测与失配反馈

监督数据：分两层获取

A
FineART：实际轨迹的未来后果

用 (当前图像、已执行动作段、未来图像/机器人状态) 构建 retrospective labels。可验证语言 state prediction 的基础学习能力，但每个起点通常只有一条真实动作轨迹，不能据此断言对反事实动作同样准确。

B
RoboTwin：候选动作干预的未来后果

使用公开仿真评估环境生成 rollouts；在能确保相同初态重置的前提下，给同一观察施加不同参数/方向的候选动作，并记录真实后果。若不能精确恢复状态，先验证 reset / replay 的可复现性，再开展 paired 评估。

标签可靠性：优先用仿真真值/object relation/接触事件生成后果；视觉无法直接验证的字段标 unknown。若用 VLM 标注未来图像，需抽检，并严格禁止未来帧进入模型推理输入。

未来后果字段示例

{
  "task": "Place cup in tray",
  "candidate_step": {
     "left": ["move z -3.0"]
  },
  "predicted_future": {
     "grasp": "cup still held",
     "relation": "cup above tray",
     "contact": "none",
     "task_complete": false
  }
}
// 示意：prediction 需与真实 future state 对照
终止不应由自述的 “done” 单独确认；应将模型的停止请求与任务判定/真实后果检查区分开。

按最小闭环 → 联合学习逐步增加实验

组别输入与预测是否改变实际动作为什么保留
P0 Direct观察 → 直接输出动作常规执行基础 policy 基线
P1 CoT观察 → 额外推理 → 动作可能排除“只要多想一些 token 就会更好”
P2 Future-SFT同一模型训练动作与未来语义 loss，推理时直接行动不显式重排测试预测监督能否改善共享表征
P3 Rerank生成 K 个动作 → 预测各自的未来 → 打分执行是测试显式预测的决策价值
P4 FeedbackP3 + 执行后比较预测与观测、必要时修正是测试失配检测与恢复能力
对照 Controls随机 K 选一 / 无未来的打分器 / 仿真真值 Oracle分组评估区分“预测有用”与“采样更多有用”；Oracle 只是上界
先做 P3 的 training-free 原型：用可用模型生成候选并直接询问未来后果，检查结果是否对动作敏感；如存在可用信号，再做 P2 的未来状态监督与 P3/P4 联合验证。保证所有组的动作执行规则一致，并同时报告决策时延与额外模型调用成本。
03 / DECISION GATES

如何判断继续、改进还是停止

每阶段必须有真正验证核心问题的指标与明确失败解释。

M1 / DATA & ACTION

转换和 SFT 是否可信

动作解析率、FK/IK 有效率、末端位置与方向误差、夹爪切换、分任务误差、VQA 能力保持。

M2 / PREDICTIVE SEMANTICS

是不是真的在预判动作后果

Future-F1 / 属性准确率、校准误差、同初态不同动作的 paired future discrimination（两选一随机水平 50%）。

M3 / CLOSED LOOP

是否真正提高操作质量

任务 success rate、失败恢复率、执行步数、碰撞/误操作、wall-clock latency、额外推理开销。

G0 DATA CONVERSION

动作可执行吗？

同一段机器人轨迹的 joint ↔ EEF ↔ 指令映射有可量化且可接受的误差，语义 steps 可由控制接口执行。

若失败：先采用 joint-relative 文本动作；不急于复制 nanoAstra 的末端指令集。
G1 SFT VALIDATION

语义处理带来收益吗？

R1/R2 对照有稳定有效的动作或事件预测改进；R3 能维持通用 VLM 能力，且不是仅仅 loss 下降。

若失败：拆查事件切分、数字精度、语言噪声、坐标系、token 预算，不继续盲目放大数据。
G2 CONTROL VALUE

未来预测改善决策吗？

未来标签对候选动作有显著区分能力；P3/P4 在相同测试集上优于 P0/P1 与等预算采样基线，同时记录时延。

若失败：区分预测不准、打分不准、动作候选太差与时延抵消收益；可保留预测学习但不强推在线规划。

建议执行节奏

周数仅供排期；首次试验以模型、标注质量与评测能跑通为准。

初期以 1 个 A800 级节点可做的小规模适配为前提
W0
数据抽检 + 动作标准化

200–500 episodes；运动学与对齐审计；固定测试集。

W1–2
R0–R3 小规模 SFT

统一 Qwen 基座与 LoRA 设置，完成离线指标和表示消融。

W3–4
未来语义样本 + 反事实

构建 o,a→future 标签；先完成 paired future 判断。

W5+
候选动作筛选与闭环

P0–P4 + Oracle 对照；形成成功率、恢复与时延报告。

资源优先级

  • 先不做全量数据训练。FineART 全量约 1.86 TB，先用选定 episodes 或 StreamingLeRobotDataset。
  • 模型保持单一主干。Qwen3.5-9B 先做 LoRA/QLoRA；如果显存不足，减少相机、分辨率、上下文和 batch，而不是同步改任务定义。
  • nanoAstra 公开了权重、推理和 RoboTwin 评估入口。完整数据处理和训练配方需要按论文与现有工具自行实现、逐项核实代码是否已有支持。
  • 闭环与离线分别报。FineART 机器人与 RoboTwin 仿真执行接口不同；不得直接把离线动作误差当作 RoboTwin success。

后续研究边界

  • 最接近工作：Semantic World Models 已经提出动作条件未来语义预测与规划；FineART-VLA 已经训练语言子任务 + 动作。
  • 可形成的新增贡献：统一文本动作模型中的细粒度动作后果预测、动作敏感的语义监督、预测与真实观测失配驱动的闭环纠正。
  • 梯度别混淆：未来文本 SFT 的 token loss 可反传到共享 VLM；但离散动作采样后，经仿真执行并不自动可微。RL / 连续动作优化作为后续独立探索。
  • 当前不做：视频生成 WM、复杂多分支专家、大规模反向规划、全量 FineART+仿真联合预训练。
